01시작하기

모든 명령은 ElevenLabs SDK가 설치된 venv의 파이썬으로 실행합니다.

파이썬 경로

%USERPROFILE%\.claude\mcp-servers\elevenlabs\venv\Scripts\python.exe

PowerShell에서는 & "$env:USERPROFILE\.claude\mcp-servers\elevenlabs\venv\Scripts\python.exe" 형태로 호출합니다. 아래 예시는 이 경로를 PY로 줄여 씁니다.

API 키

사용자 환경변수 ELEVENLABS_API_KEY를 읽습니다. 키에 user_read 권한이 있어야 크레딧 잔량을 조회할 수 있습니다. 없어도 생성 자체는 되지만 비용 게이트가 동작하지 않습니다.

스크립트 형식

파일명이 ElevenLabs 보이스 이름입니다. Closers_Android.txt는 계정의 Closers_Android 보이스로 생성됩니다. 프로젝트 폴더에 .txt를 넣으면 자동으로 인식됩니다.

(스타일)[오디오태그] 텍스트 | NNNN.wav

두 태그 모두 선택사항입니다.

(행복)[happy] 오늘은 정말 즐거운 날이에요! | 0001.wav
(슬픔)[sad] 다시 만날 수 있을까요. | 0002.wav
[neutral] 목적지에 도착했습니다. | 0003.wav
남은 화살은 62발입니다. | 0004.wav

두 태그의 역할이 다릅니다

태그하는 일API 전송
(행복) 클립을 wavs/행복/ 폴더에 저장합니다. 분류 라벨입니다 안 함 — 과금 문자에 포함되지 않습니다
[happy] 모델에게 이 감정으로 연기하라고 지시합니다 함 — [neutral]만 생략됩니다

스타일 이름이 곧 폴더 이름이 됩니다. 그래서 파서가 경로 구분자, .., Windows 예약어(con, com1 등)를 거부합니다. wav 파일명은 스타일이 달라도 전체에서 유일해야 합니다 — 다른 모든 곳에서 클립을 식별하는 이름이기 때문입니다.

웹앱 실행

PY -m webapp
# http://127.0.0.1:8765

루프백 전용입니다. 인증이 없고, 프로세스가 API 키를 들고 있으며, 크레딧을 쓸 수 있습니다. --host로 외부에 노출하지 마세요.

02작업 흐름

순서가 중요합니다. 3번까지는 크레딧이 들지 않고, 4번에서 처음으로 돈이 나갑니다.

01

스크립트 배치무료

보이스 이름과 똑같은 이름의 .txt를 프로젝트 폴더에 둡니다. 웹앱 Scripts 탭이나 preview가 파싱 오류를 바로 알려줍니다.

02

정규화 검수무료

숫자를 한글로 펼치고 조사를 교정한 결과를 확인합니다. 여기서 반드시 단어 재작성 목록을 읽으세요. 실제 명사가 섞여 있으면 데이터셋 전체가 오염됩니다.

PY -m tts_batch preview Closers_Android.txt
03

비용 확인무료

과금 문자 수와 잔여 크레딧을 비교합니다. 부족하면 여기서 멈춥니다.

PY -m tts_batch estimate Closers_Android.txt
04

파일럿 50건유료

전체를 돌리기 전에 소량으로 톤·숫자 발음·감정 표현을 귀로 확인합니다. 실제로 이 단계에서 두 개의 버그가 잡혔습니다.

PY -m tts_batch generate Closers_Android.txt --limit 50
05

전체 생성유료

이미 만든 클립은 건너뜁니다. 중단해도 이어서 진행되고 중복 과금이 없습니다. 동시 요청 5개 기준 4,211건에 약 26분.

PY -m tts_batch generate Closers_Android.txt
06

수리와 검수무료

retrim으로 앞뒤 무음을 맞추고, declick으로 끝부분 틱을 잘라냅니다. 둘 다 --check로 먼저 보고, 실행 후에는 웹앱 Review 탭에서 들어봅니다.

PY -m tts_batch retrim Closers_Android.txt --check
PY -m tts_batch declick Closers_Android.txt --check

03웹앱

CLI와 같은 6개 작업을 브라우저에서 합니다. 서버는 tts_batch를 감싸기만 하므로 두 경로의 결과가 항상 같습니다.

탭하는 일
Scripts스크립트 목록, 보이스 매칭, 생성 진행률
Preview정규화 요약, 단어 재작성 감사(클릭 한 번으로 보호 목록 추가), 줄 단위 diff 검색
Generate실행 전 비용 확인, 실시간 진행률, 중단 버튼, 실패·플래그 재생성
Review클립 재생·파형, 플래그 필터, 잘라내기 전후 나란히 비교, 개별 되돌리기
Toolsretrim·declick의 검사 모드와 실행 모드

작업은 한 번에 하나만 돌아갑니다. 실행 중에 다른 작업을 요청하면 거부됩니다. 진행률은 서버가 밀어주므로 페이지를 나중에 열어도 현재 상태가 그대로 보입니다.

05함정

전부 실제로 겪은 것들입니다. 새 보이스를 시작할 때 이 목록부터 확인하세요.

단어 재작성이 명사를 망가뜨린다 치명적

조사 교정은 단어를 고쳐 씁니다. 형태소 분석이 없어서 실제 명사를 명사+조사로 오인할 수 있습니다. 계절 가을이 가+을로 읽혀 가를 축제가 될 뻔했습니다.

생성 전에 preview의 단어 재작성 목록을 한 줄씩 읽으세요. 진짜 문법 교정이 아닌 항목은 웹앱에서 클릭 한 번으로 보호 목록에 넣을 수 있습니다.

가을 축제 → 가를 축제  ·  20건 · 사전 검수로 차단

declick이 마지막 단어를 자를 수 있다 치명적

틱과 단어를 가르는 기준은 ARTIFACT_MAX_MS입니다. 500ms였을 때 480ms짜리 정상적인 마지막 단어를 틱으로 판정해 잘라냈습니다. 현재는 200ms입니다.

실측상 이 코퍼스의 틱은 55건이 정확히 20ms, 실제 발화는 480ms로 명확히 갈렸습니다. 다른 보이스에서는 경계가 다를 수 있으니 declick 후 Review 탭에서 반드시 들어보세요. 원본은 originals/에 자동 백업되어 되돌릴 수 있습니다.

2718.wav · 480ms 마지막 단어 절단 · 백업에서 복원

고정 길이로 잘라내면 안 된다 주의

편차는 틱이 아니라 틱 앞의 공백에 있습니다. 틱은 20ms로 일정한데 공백이 100~420ms로 벌어져 잘라낼 총량이 5배 차이납니다. 가장 긴 610ms로 일괄 절단하면 56건 중 55건이 실제 발화를 잃습니다.

declick은 클립마다 감지된 발화 끝 지점에서 자릅니다.

seed가 고정이라 재생성해도 같은 오디오가 나온다 주의

클립 ID로 seed를 만들어 재현성을 보장합니다. 그래서 retry는 seed 오프셋을 올려야 다른 테이크가 나옵니다. 기본 --take 1, 또 실패하면 --take 2로 올립니다. 사용된 seed는 매니페스트에 남습니다.

트림이 가끔 적용되지 않는다 주의

4,211건 중 39건(0.9%)이 생성 시 트림을 건너뛰었습니다. 같은 텍스트로 다시 호출하면 정상 동작해서 원인을 재현하지 못했습니다.

그래서 생성 시 트림을 신뢰하지 않고 사후 검증합니다. 배치가 끝날 때마다 retrim을 돌리세요. 멱등성이 있고 비용이 없습니다.

44.1kHz는 Creator 티어에서 막혀 있다 주의

pcm_44100은 Pro 티어 전용입니다. 다만 업그레이드할 이유가 없습니다 — 24kHz의 나이퀴스트 한계(11,025Hz) 위쪽 에너지가 전체의 0.32%뿐이고 16kHz 이상은 0입니다. 모델이 그 대역에 아무것도 만들지 않습니다.

mp3_44100_192는 샘플레이트만 높고 손실 압축이라 현재의 24kHz 무손실보다 나쁩니다.

06산출물

output/<보이스>/ ├─ wavs/NNNN.wav 24kHz 모노 16bit PCM │ └─ 행복/NNNN.wav 스타일 태그가 있으면 폴더로 나뉩니다 ├─ originals/ declick 이전 원본, wavs/ 구조를 그대로 따름 ├─ metadata.csv id|transcript|emotion|style — LJSpeech 형식 ├─ manifest.jsonl seed·파라미터·QC 측정치 전체 기록 ├─ qc_flags.csv 들어봐야 할 클립 ├─ failures.csv 끝내 실패한 클립 ├─ preview.txt 원문 → 발화 → 전송, 전 줄 ├─ changes.txt 변경된 줄만 └─ josa_changes.txt 조사 교정 감사

id가 파일 경로입니다

metadata.csv의 첫 열은 wavs/ 기준 상대 경로에서 확장자를 뺀 것입니다. 스타일이 있으면 행복/0001, 없으면 0001 — 어느 쪽이든 바로 파일로 해석됩니다. 스타일 기능 이전에 만들어진 3열짜리 행은 4열로 채워질 뿐 내용이 바뀌지 않습니다.

transcript가 오디오와 일치합니다

metadata.csv의 텍스트는 정규화 후의 문장입니다. 43636이 아니라 사만 삼천육백삼십육이 적힙니다. 서버 정규화를 끄고 직접 변환하기 때문에 학습에 필요한 transcript↔오디오 일치가 보장됩니다.

QC 리포트는 덮어쓰기 방식입니다. 깨끗해진 클립은 목록에서 빠지고, 비면 파일 자체가 삭제됩니다. 그래서 retry가 이미 고친 클립을 다시 만들지 않습니다.

07설정 조정

위치설정현재값과 이유
cli.py DEFAULTS 모델 eleven_v3, pcm_24000, apply_text_normalization="off"(직접 정규화하므로), 동시 5(Creator 한도), [neutral] 태그 생략
audio.py ARTIFACT_MAX_MS 200 — 새 보이스에서 가장 먼저 재조정이 필요한 값
audio.py ARTIFACT_GAP_MS 100 — 틱을 발화에서 분리하는 최소 공백
normalize.py PROTECTED_TOKENS 조사처럼 끝나는 명사. preview에서 발견하면 여기 추가
normalize.py COUNTERS 단위별 수사 체계. 개·명·곳·발·배·시간은 고유어, 퍼센트·미터·분·초·시·월·일은 한자어

[neutral]을 생략하는 이유

측정 결과입니다. 태그를 넣은 것과 뺀 것의 차이가 ±0.08초로 v3의 일반적인 생성 편차 안이었고, 태그 자체가 과금 문자에 포함되어 이 스크립트에서만 35,150자였습니다.

숫자 읽기 규칙

고유어 수사는 99까지만 쓰고 그 이상은 한자어로 넘어갑니다 — 295발은 이백구십오 발입니다. 일은 문맥으로 갈립니다: 7월 10일은 칠월 십일로 붙이고, 5일 남았습니다는 오 일로 띄웁니다. 붙이면 기름(오일)으로 들립니다.

08문제 해결

증상확인할 것
보이스를 못 찾음 스크립트 파일명과 ElevenLabs 보이스 이름이 정확히 일치해야 합니다. 대소문자 포함
크레딧 조회 실패 API 키에 user_read 권한이 있는지. 없으면 생성은 되지만 비용 게이트가 꺼집니다
숫자를 한 자씩 읽음 정규화를 거치지 않은 텍스트가 전송된 경우입니다. preview.txt의 send: 줄을 확인하세요
재생성해도 잡음이 그대로 --take 값을 올리세요. 같은 값은 같은 seed라 같은 오디오가 나옵니다
보호 목록 추가가 반영 안 됨 웹앱에서 추가했다면 서버를 재시작해야 합니다
웹앱에서 작업이 거부됨 이미 다른 작업이 돌고 있습니다. 상단 작업 바에서 중단하거나 끝날 때까지 기다리세요
생성이 중간에 끊김 같은 명령을 다시 실행하면 됩니다. 이미 만든 클립은 건너뛰므로 중복 과금이 없습니다
